Suggested additions, with evidence

Where existing destination components fall short, and what to build or compose.

Component comparisonsSuggested additionsACF & shared contentGaps & page recipesOriginal guides

Build where the gap affects content or behavior

These 12 suggestions come from the repaired component review. Priority 1 addresses navigation, page structure and service continuity. Priority 2 provides reusable editorial patterns. Conditional items need additional work only when their particular behavior is retained.

Each entry pairs the legacy example or inventory evidence with an existing FYE starting point, explains the missing capability, and outlines a proposed addition. A proposed pattern can use existing blocks; it does not automatically need a new custom block.

Evidence limits: templates are schematics; calendars and equipment forms are inventory-only; video and optional portrait needs come from documented options. Examples use sample content. Interactive previews demonstrate the repaired extraction, not live WordPress compatibility.

Priority 1New component

Section navigation

Keep orientation within a department or section when the legacy page tree is still required.

Evidence of the gap

The legacy example shows nested page links. The FYE Secondary header example shows an introduction and action, without that tree. Its curated navigation option does not establish automatic ancestor/sibling/child behavior.

A static preview cannot prove tree generation. The need also follows the source Sidebar Nav Settings fields. A curated header menu is sufficient if automatic hierarchy is deliberately retired.

Proposed structure

Concept only — this describes the suggested addition; it is not an implemented destination component.

Determine current sectionShow parent and nested pagesMark current pageCollapse appropriately on mobile

Ready when: Changing page hierarchy updates the navigation; current-page state and direct child links work on desktop and mobile.

The source is a schematic, not a live page capture. Build these layouts only if sidebars are retained; a deliberate single-column redesign can use existing blocks.

Header and breadcrumbsSection navigation + main content + sidebarOptional wide sections belowDefined mobile reading order

Retain masonry and image enlargement if those are required parts of the experience.

The repaired source shows mixed-ratio masonry and opens an enlargement overlay. The destination example shows a regular Gallery grid; it does not establish equivalent enlargement behavior.

If a regular grid is acceptable, use Gallery directly. Slider changes the browsing experience and is not a masonry replacement.
